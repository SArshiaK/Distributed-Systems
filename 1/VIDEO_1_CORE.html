🎬 ویدیو ۱ — بخش اصلی تمرین (Core Assignment)

این ویدیو برای نشان دادن بخش اصلی (بدون بونوس) طراحی شده و شامل موارد زیر است: معرفی محیط، عملیات عادی، مدیریت خطاها، همزمانی و Isolation، Atomicity، Durability و نمایش لاگ‌ها.
مدت زمان تقریبی: حدود ۳.۵ دقیقه

آماده‌سازی قبل از شروع ضبط

  • Witness روی هاست ویندوز در حال اجراست (پورت 9000)
  • Server A روی VM اول فعال است (پورت 8000)
  • Server B روی VM دوم فعال است (پورت 8000)
  • کلاینت روی VM سوم دسترسی به هر دو سرور دارد
  • موجودی اولیه A1001 به ۱۰۰۰ ریست شده:
sudo -u postgres psql -d minibank -c "UPDATE accounts SET balance = 1000.00 WHERE account_id = 'A1001';"

چیدمان صفحه (۴ ترمینال کنار هم):

Host ویندوز: ترمینال witness.pyServer A: ترمینال server.py
Server B: ترمینال server.pyClient: ترمینال دستورات

بخش ۱ — معرفی سیستم (۰:۰۰ — ۰:۳۰)

متن پیشنهادی برای روایت صوتی:

"این پروژه، یک سامانه بانکی کوچک توزیع‌شده با نام Mini Banking Server است. ارتباط بین ماشین‌ها بر بستر HTTP با داده‌های JSON انجام می‌شود. ما یک گره داور (Witness) به آدرس .103 داریم که برای رأی‌گیری حدنصاب استفاده می‌شود؛ سرور اصلی A به آدرس .101؛ سرور پشتیبان B به آدرس .104؛ و کلاینت به آدرس .102. پایگاه داده ما PostgreSQL است با مکانیزم Streaming Replication و کنترل همزمانی از طریق قفل‌گذاری سطری."

بخش ۲ — عملیات عادی بانکی (۰:۳۰ — ۱:۰۰)

دستورات در ترمینال Client VM:

python3 client.py balance A1001
python3 client.py deposit A1001 100
python3 client.py withdraw A1001 50
python3 client.py balance A1001

روایت:

"ابتدا موجودی حساب A1001 را استعلام می‌کنیم: ۱۰۰۰ تومان. سپس ۱۰۰ تومان واریز می‌کنیم — موجودی به ۱۱۰۰ تغییر می‌کند. پس از برداشت ۵۰ تومان، موجودی نهایی ۱۰۵۰ می‌شود. هر تراکنش قبل از ارسال پاسخ موفق، در دیسک Commit می‌شود."

بخش ۳ — مدیریت جامع خطاها (۱:۰۰ — ۱:۴۵)

دستورات در ترمینال Client VM:

python3 client.py errors

جدول خطاهای نمایش داده شده:

خطاکد HTTPپیام
حساب ناموجود (Z9999)404unknown account: Z9999
موجودی ناکافی400insufficient funds
مقادیر منفی یا صفر400amount must be a positive number
مقدار invalid (مثل abc)400amount must be a positive number
عملیات پشتیبانی نشده (transfer)400unsupported action: transfer
فیلد ناقص400missing amount field
JSON خراب400malformed request

روایت:

"حالا هشت زمینه اصلی خطا را پوشش می‌دهیم: حساب ناموجود با کد ۴۰۴، موجودی ناکافی، مقادیر منفی، صفر یا نامعتبر، اکشن ناشناخته، فیلدهای گم‌شده و JSON خراب — تمام خطاها با کدهای درست HTTP پاسخ می‌دهند و سرور همچنان در حال اجراست و crash نمی‌کند."

بخش ۴ — همزمانی و Isolation (۱:۴۵ — ۲:۲۰)

دستورات در ترمینال Client VM:

python3 client.py stress A1001 20 10

روایت:

"۲۰ کلاینت همزمان برای برداشت ۱۰ تومانی اقدام می‌کنند. خروجی می‌گوید OK — matches serial expectation؛ یعنی موجودی نهایی دقیقاً برابر با ترتیب سریال تراکنش‌هاست، هیچ Lost Update رخ نداده. این اثباتی قطعی از Isolation با قفل سطری SELECT FOR UPDATE است."

بخش ۵ — Atomicity (۲:۲۰ — ۲:۴۰)

دستورات در ترمینال Client VM:

python3 client.py withdraw A1001 999999
python3 client.py balance A1001

روایت:

"سعی می‌کنیم برداشت غیرممکن انجام دهیم. تراکنش شکست می‌خورد و هیچ تأثیری روی موجودی نمی‌گذارد — این اثبات Atomicity است."

بخش ۶ — Durability (۲:۴۰ — ۳:۱۰)

دستورات در ترمینال Server A:

# کشتن سرور با Ctrl+C، سپس:
python3 server.py   # راه‌اندازی مجدد

دستورات در ترمینال Client VM:

python3 client.py balance A1001

روایت:

"حالا سرور اصلی A را می‌کشیم و دوباره راه‌اندازی می‌کنیم. موجودی دقیقاً همان عدد قبلی است — هیچ چیز از دست نمی‌رود. چون تراکنش Commit شده روی Write-Ahead Log دیسک ثبت گردیده، هیچ داده‌ای از دست نرفته. این اثباتی از Durability است."

بخش ۷ — نمایش لاگ‌ها (۳:۱۰ — ۳:۳۰)

دستورات در ترمینال Server A:

cat bank_server.log

روایت پایانی:

"هر درخواست، همراه با زمان، شناسه ریکوئست، IP کلاینت، اکشن، حساب، وضعیت و latency در فایل bank_server.log ذخیره شده است. تمامی خواسته‌های بخش اصلی تمرین با موفقیت اعمال شدند. از وقتی که وقت داده‌اید سپاس‌گزارم."
